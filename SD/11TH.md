# Token Buckets:
        The Token Bucket is a rate-limiting algorithm used in networking and systems to control how many requests a user/client can make in a given period.

Think of it like a bucket containing tokens:

             Tokens
          ↓ ↓ ↓ ↓ ↓
       ┌─────────────┐
       │ ● ● ● ● ●   │  ← Bucket
       │ ● ●         │
       └──────┬──────┘
              │
              ↓
         Incoming Request
              │
        Token available?
          /          \
        YES           NO
         ↓             ↓
   Allow request     Reject/
                    wait


Suppose:

Bucket capacity = 5 tokens
Tokens are added at 2 tokens/second
Each request consumes 1 token

Initially:

    Bucket = 5 tokens

If 5 requests arrive:

Request 1 → 4 tokens
Request 2 → 3 tokens
Request 3 → 2 tokens
Request 4 → 1 token
Request 5 → 0 tokens

A 6th request arrives:

No token → Request rejected/throttled

After some time, tokens are added:

After 1 sec → +2 tokens
Bucket = 2

Now two more requests can be processed.


# Leaky Bucket

    The Leaky Bucket is a traffic shaping / rate-limiting algorithm used in computer networks to control the rate at which packets or requests leave a system.


Incoming packets
   ↓ ↓ ↓ ↓ ↓
┌──────────────┐
│              │
│    BUCKET    │
│  packets     │
│  packets     │
│  packets     │
└──────┬───────┘
       │
       ↓
   Fixed rate
       ↓
     Server

Suppose:

Bucket capacity = 5 packets
Output rate = 1 packet/second

If 5 packets arrive quickly:

Time 0:
  P1 P2 P3 P4 P5
  ↓  ↓  ↓  ↓  ↓
┌─────────────┐
│ P1 P2 P3 P4 P5 │
└──────┬──────┘
       ↓
      P1

Then the remaining packets leave at a fixed rate:

1 sec → P2
2 sec → P3
3 sec → P4
4 sec → P5

So even if packets arrive in a huge burst, the server receives them at a controlled rate.

What if the bucket is full?

Suppose capacity is 5:

P1 P2 P3 P4 P5

Another packet arrives:

P6 → Bucket FULL → DROP P6

So packets can be dropped when the bucket overflows.


## THROTLING

    Throttling means limiting how fast or how often a user/client can access a resource.

Throttling is the process of limiting the rate at which a client can send requests to a system in order to protect system resources and maintain performance.

# FIXED WINDOW COUNTER

Fixed Window Counter is a rate-limiting algorithm that divides time into fixed intervals and limits the number of requests allowed in each interval.

Suppose:

Limit = 5 requests
Window = 1 minute
        1 minute
|----------------------|
  5 requests allowed

Requests:

Request 1 ✅
Request 2 ✅
Request 3 ✅
Request 4 ✅
Request 5 ✅
Request 6 ❌

When the 1-minute window ends, the counter resets:

New minute
Counter = 0

Request 1 ✅
Request 2 ✅
..........


# SLIDING WINDOW LOGS  (BEST ONE)

Sliding Window Log is a rate-limiting algorithm that stores the timestamp of every request and checks how many requests occurred in the most recent time window.


5 requests per 10 seconds

Instead of fixed windows like:

0s ────────── 10s ────────── 20s
   Window 1       Window 2

the window moves continuously.

If the current time is 12 seconds, we look at:

2s ───────────────── 12s
        10-second window
How it works

Suppose requests arrive at:

2s
4s
5s
8s
11s

At 12s, the sliding window is:

2s ───────────────── 12s
↑                    ↑
oldest               current

All 5 requests are inside the window:

2, 4, 5, 8, 11

So:

5 requests → Limit reached → New request not allowed
